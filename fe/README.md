## 스크린샷 폴더 고정

`설정 → 스크린샷 폴더 → 폴더 지정`에서 오버워치 스크린샷 폴더를 한 번 선택합니다.

폴더 접근 권한은 브라우저의 File System Access 기능과 IndexedDB를 이용해 보관합니다.
브라우저 보안상 Windows의 전체 경로 문자열 자체를 저장하거나 표시하는 방식이 아니라, 선택한 폴더의 접근 핸들을 저장합니다.

이후 `/matches/new`에서는:
1. 저장된 폴더를 자동으로 찾음
2. 필요할 때만 브라우저 권한을 재확인
3. 마지막 처리 이후의 새 이미지부터 확인
4. 요약 화면을 기준으로 경기를 묶음

설정에서 `경기 등록 화면에서 자동으로 새 파일 확인`을 켜면 권한이 유지된 경우 페이지 진입과 함께 스캔합니다.

Windows Chrome 또는 Edge + localhost 사용을 권장합니다.

## 가설 구조

사용자가 가설을 직접 작성하지 않습니다.

ORCA가 처음부터 100개의 사전 가설 Library를 가지고 있고, 데이터가 쌓이면 각 가설의 최소 표본과 필수 데이터 준비 상태를 계산합니다.

현재 사전 가설 영역:
- 개인 퍼포먼스
- 팀 상대값
- 맵 / 상황
- 아군 / 상대 조합
- 패치 / 메타
- 장기 변화 / 세션 / 듀오
- 리플레이 타임라인 기반 후보

대표 예시:
- 데스 / 10분과 승률
- 팀 딜 비중
- 같은 역할 상대와의 성과 차이
- 맵 × 내 영웅
- 선공 / 선수비
- 세션 첫 경기 / 장시간 플레이 피로
- 연승 / 연패 구간
- 특정 아군 및 상대 영웅 상성
- 조합 스타일
- 상대 카운터 밀도
- 패치 적응 속도
- 메타와 개인 강점의 불일치
- 티어 상승 / 하락 전 선행 지표
- 듀오 × 영웅 / 맵 상호작용
- 첫 데스 / 첫 교전 / 연장전 등 리플레이 타임라인 가설

이후 ML이 발견한 패턴은 별도의 candidate 가설로 추가하는 구조입니다.

## 주요 경로
- `/` : 대시보드
- `/login` : ORCA 로그인
- `/matches/new` : 경기 등록 / 자동 분류
- `/matches` : 경기 목록
- `/matches/[id]` : 경기 상세 / 수정 / 삭제 / OCR 검수
- `/analysis` : 확정 경기 기초 분석
- `/insights` : 최근 변화 / 데이터 완성도 / 다음 검증 포인트
- `/hypotheses` : 사전 가설 Registry
- `/settings` : 스크린샷 폴더 / 개발 환경 / Mock 데이터 관리

## 경기 등록 일괄 검수

자동 분류 후 `전체 검수 시작`을 누르면 검수 화면을 빠져나가지 않고 모든 경기를 연속으로 확인합니다.

- 상단에서 경기 1/N 진행률 표시
- 전체 경기 빠른 이동
- 이전 경기 / 다음 경기
- 현재 경기의 자동 분류 수정
- `검수 완료 · 다음 경기` 한 번으로 저장 후 다음 경기 이동
- 이미 완료한 경기 재검수 가능

## 경기 상세 OCR 검수
현재 Mock 환경에서도 실제 OCR 결과가 들어올 자리를 미리 만들었습니다.

- 우리 팀 5명
- 상대 팀 5명
- 닉네임
- 영웅
- 처치
- 도움
- 죽음
- 피해
- 치유
- 피해 경감
- 내 플레이 영웅
- 플레이 시간
- 명중률
- 치명타
- 영웅 고유 지표

검수 초안은 브라우저 localStorage에 자동 저장됩니다.

## 현재 구조

```
UI
  ↓
MatchManagementAdapter
  ↓
Mock Backend (현재)
  ↓
실제 Supabase / OCR Adapter (추후 교체)
```

백엔드 구조가 확정되기 전까지 Supabase 경기 저장과 Python OCR 호출은 UI에 직접 섞지 않습니다.

## Supabase 로그인 설정
`fe/.env.example`을 참고해 `.env.local`을 만듭니다.

```
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=...
```

환경변수가 없으면 Mock 모드로 계속 사용할 수 있습니다.
